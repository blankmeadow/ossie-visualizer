# 个人英语词库 · MVP

> 家长只负责把学习内容加进来，孩子每天只负责「开始学习」；其余工作由系统自动完成。

把孩子在教材、绘本、练习册里真实遇到的英语拍进来，系统自动提取值得学习的**单词和短语**、
保留**原文例句**，再通过间隔重复和渐进式题型帮孩子真正记住。

```
孩子遇到新的英语 → 家长添加到词库 → 系统自动整理 → 系统自动安排 → 孩子每天学习 → 逐渐掌握
```

## 快速开始

### 1. 后端

```bash
cd backend
./run.sh                      # 自动建 venv、装依赖、启动
```

服务跑在 <http://127.0.0.1:8000>，接口文档在 <http://127.0.0.1:8000/docs>。

**不需要任何 API Key。** 默认 `AI_PROVIDER=mock`，管线用内置的示例教材页跑通全流程。

灌一份演示数据（约 40 个单词短语 + 6 天连续学习记录）：

```bash
.venv/bin/python -m app.seed --reset
```

### 2. App

```bash
cd mobile
npm install
npm run web                   # 浏览器里直接看
# 或
npm start                     # 用 Expo Go 扫码在手机上跑
```

> 真机调试时把 `mobile/app.json` 里的 `extra.apiBaseUrl` 改成电脑的局域网 IP，
> 例如 `http://192.168.1.10:8000`，否则手机连不上 `127.0.0.1`。

### 3. 接真实的 AI 识别

```bash
cd backend
cp .env.example .env
# 在 .env 里填：
#   KIDVOCAB_AI_PROVIDER=anthropic
#   KIDVOCAB_ANTHROPIC_API_KEY=sk-ant-...
```

一次 Vision 调用完成 OCR、正文还原、句子恢复和候选提取；之后的词形归一、短语优先、
学习价值判断、个人词库去重全部由本地确定性代码接管，所以换任何模型都不会把词库搞脏。

## 已实现的 MVP 功能

### 内容输入
- [x] 词库 ＋ 统一添加入口（拍照 / 相册 / 手动）
- [x] 多图上传，一次最多 10 张，可删除、可调整顺序
- [x] 手动添加：输入一个词，系统自动补标准形式、词性、释义、音标

### AI 整理
- [x] OCR / 正文恢复（断词回接、题号剥离、中文释义列剥离）
- [x] 句子切分，并区分「可做例句的完整句」与「词表条目」
- [x] **短语优先**：`looking for` → `look for`，绝不拆成 `look`
- [x] 词形归一：`dogs→dog`、`went→go`、`running→run`、`taking care of→take care of`
- [x] 学习价值判断：过滤功能词、专有名词、OCR 噪声、超纲词
- [x] 个人词库去重：已有词自动合并，不弹「是否覆盖」
- [x] 原文例句关联，保存精确到字符的 offset

### 词库
- [x] 单词 / 短语统一管理、筛选、搜索
- [x] 详情页最多展示 3 条原文例句，后台保存全部 occurrence
- [x] 再次遇到 → `seen_count + 1`、更新 `last_seen_at`、追加新例句

### 学习
- [x] 今日任务：到期复习优先，不足再补新内容，上限 = 每日学习量
- [x] 首次学习卡（不立即考试，但本轮内会被考到）
- [x] T1 英→中 / T2 中→英 / T3 挖空 / T4 完整填写 / T5 原文例句挖空
- [x] 渐进式提示，用提示后不升级复习间隔
- [x] 答错不打叉、不扣分，本轮稍后再出现（有次数上限，不会卡死）
- [x] 严格单向推进：没有上一题 / 下一题 / 滑动 / 跳题

### 记忆
- [x] Mastery 四个独立分数（meaning / reverse / spelling / context）
- [x] SRS 独立于 Mastery：当天 → 1 → 2 → 4 → 7 → 15 → 30 天
- [x] 题型自动升级与降级（连续答错两次自动降难度）
- [x] ReviewLog 全量保留，为后续换 FSRS 或自研模型攒数据

### 商业化
- [x] Feature / Entitlement 模型，免费额度是「发放时的默认值」而非代码常量
- [x] 拍照 + 相册共享 AI 导入额度，默认累计 3 次
- [x] **分析成功且有结果才扣额度**；失败、无内容、用户取消都不扣
- [x] 额度耗尽只在「拍照 / 相册」处弹付费墙，且明确保留免费手动添加
- [x] 学习、复习、词库容量、五种题型永不收费

## 设计上几个关键取舍

**Mastery 和 SRS 必须分开。**
一个笼统的 `mastery = 72%` 回答不了「下一题考什么」。
认得 `forest` 但拼不出来的孩子，`meaning_score` 高、`spelling_score` 低，
下一题就该是挖空而不是选择题。所以四个技能分独立记录，SRS 只回答「什么时候再考」。

**免费次数不能写死。**
`free_ai_image_import_quota = 3` 只在**开户发放额度那一刻**被读一次。
之后所有代码问的都是「这个用户 `AI_IMAGE_IMPORT` 还有额度吗」，
所以改成「每月 1 次」「邀请加 3 次」「Pro 每月 100 页」都不用碰导入管线。

**扣费扣在交付上，不扣在尝试上。**
识别失败、图片看不清、没提取到内容 —— 一次都不扣。
家长第一次用就被扣掉一次却什么都没得到，是最伤留存的体验。

**答错必须回来，但不能无限回来。**
规格要求答错的词「本轮后面再次出现」。但如果孩子就是不会，
无限重排会让这一轮永远结束不了，所以每个词每天最多额外出现 2 次，其余交给明天的复习。

**干扰项必须合情合理。**
`forest` 的干扰项是 `follow / first / forget`，不是随机单词。
T5 挖空藏的是变形后的 `looking for`，所以四个选项全部变形成
`looking at / looking up / looking forward to`，否则光看形态就能猜对，
收集到的 ReviewLog 也就没有价值了。

**判题在服务端。**
客户端只提交答案，正确与否、正确答案是什么都由服务端重新推导，
连 T5 挖的是哪一句都会核对，避免客户端自报成绩污染记忆数据。
